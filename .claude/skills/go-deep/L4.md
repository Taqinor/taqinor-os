# go-deep L4 « ship-grade » — the full procedure

Read this file in full before tour 0. Templates are in `gabarits/`; every choice, its source and
its status are in `conception.md`. A number tagged **(start)** is a starting value taken from ONE
run (19-20/11), not calibrated: recalibrate it after the first L4 launched from this skill, and
log the measured value in the state file. « rétro § n » = the retrospective of that run, section n (its path
and status: `conception.md`).

L4 changes a product surface until a numeric exit contract, written before any review, is met.
It is launched only when Reda names it. It never deploys, never touches prod, and each merge goes
through the queue like any other PR.

## Token economy — read before dispatching any agent (measured 26/11/2026)

Measured on the calepinage L5 (two sessions, 619 agents, 55,000 steps, ≈ $4,600 at API prices):
56 % of the cost was agents RE-READING their own context at every step, 27 % writing new content
to the cache, 17 % thinking and output. A general-purpose agent started with 101k tokens loaded
(58k of it CLAUDE.md and the memory indexes), peaked at 271k (median) and up to 880k; 71 % of the
agent cost was spent above 200k; 88 % of steps made a single tool call. Re-pricing the same work:
lean start + bounded agents ≈ 55-60 % of that cost, ≈ 40 % if steps are grouped. Rules:

1. **Agent types** (`.claude/agents/`, they start WITHOUT CLAUDE.md and carry the house rules they
   need): fix and build lanes → `lane-legere`; reviewers and live replays → `relecteur-leger`;
   verifiers, counter-verifiers against code, CI scouts and the final critique → `verificateur-leger`
   (the built-in `Explore` / `Plan` types are the fallback for pure reading: they also skip
   CLAUDE.md). Every call still carries its explicit `model:`. A definition is loaded when the
   session STARTS (measured: one written mid-session is « not found »), and a desktop worktree
   session was seen loading its skills from the main checkout: tour 0 dispatches one trivial call
   per type; a type that is not offered is said in the cost line, and its lanes fall back to
   `general-purpose` with the two rules below.
2. **Bounded lanes**: a lane agent gets at most ~5 tasks (or what should fit in ~100 steps). The
   next chunk of the same lane is a FRESH agent starting from the lane branch's commits — never a
   `SendMessage` that keeps a 300k context alive; resume an agent only to finish the task it was
   stopped in. A lane of 15 tasks is three agents in sequence, not one.
3. **Grouped steps** are in the agent definitions (parallel reads in one message, one chained
   check command, long output to a file). A brief never asks for the opposite.
4. **The orchestrator stays small too**: one session per lot (the state file is the resume point);
   the state file keeps ONE « reprendre ici » section of ≤ 150 lines and moves older points to
   `<dossier>/etat-archive.md` (a 260,000-character state file was re-read at every resume);
   a mechanical sequence (fold + push, wait for CI) is ONE scripted call, and reading logs,
   diffs and reports is delegated — only the 15-line report enters its context.
5. **Fable** stays where CLAUDE.md puts it (final critique, adjudication): the same lane work costs
   ×1.4 on Fable instead of Opus and ×3 instead of Sonnet. A Fable critic gets a prepared bundle
   (`git diff --stat`, the list of risky files, the contract) instead of exploring from zero.
6. **Measure at each merge**: `python .claude/skills/go-deep/outils/cout_session.py <transcript
   folder of the session>` (under `~/.claude/projects/`), and write to the state file the cost at
   API prices, steps per agent (median), median peak context and the share spent above 200k.
   Baseline to beat: 76 steps, 271k, 71 %.

## Tour 0 — in this order, before any reviewer (orchestrator + ≤ 2 agents)

1. **Box** — measure, do not assume: cores (`nproc`), free memory, free disk (`df`), other stacks
   (`docker ps` only if Docker already runs; never start it). Written caps (memory
   `machine_laptop_capacite`, 10-11/11): 8 lanes plus an audit loop kept the CPU at 94-99 % —
   that is a full machine; for long runs, 3 sub-agents per session; ≈ 1 GB per lane worktree.
   From the measure, fix the number of agents driving a browser at once and write it to the
   state file. Free disk ≥ (lanes × 1 GB + 10 GB) **(start)**, else fewer lanes. No round during
   the nightly QA window (scheduled task `TAQINOR nightly QA`, 23:00). `TaqinorDevClean` (03:00 UTC)
   deletes worktrees without git activity for 7 days: state lives pushed, never only in a worktree.
2. **Regime + cost line** — run `gabarits/regime.md` on `origin/main`; read the quota with
   `mcp__ccd_session_mgmt__get_usage` (deferred tool: load it with ToolSearch; desktop app only),
   window « Weekly · all models » (and « Weekly · Fable » for a Fable orchestrator). Say in one line:
   « Régime : <…> · L4 · origin/main@<sha9> — coût estimé : <k> tours × ≈ <c> points + réserve
   finale <r>, quota à <u> %. » Unreadable quota → tour 0 only, and the line asks Reda for the
   figure. Formula: see « Cost and stop ».
3. **Claims** — `python scripts/plan_claims.py claim file:<owner plan> app:<app> --owner
   <hostname>/<branch>`, also on every OTHER owner's plan that will receive tasks (including
   `PLAN_AUDIT_TRANSVERSE.md`); `renew` at every checkpoint (the lease is 6 h, a round lasts
   hours); `release` after the merge, never at a fold (D-CLAIMS-MERGE).
4. **CI read on the intact head** — a haiku scout reads the last full CI run of `origin/main`
   (`gh run list --branch main --limit 5`, then `gh run view <id> --log`) job by job against the
   scope; the draft PR (Auto-fix on) opens with the first code commit. The question per job: « does this check actually read this module? » (on 19-20/11 api-fuzz did not read the
   module: ≈ 50 latent schema defects surfaced only later, rétro §4). Its reds and blind spots
   form **Lane 0** before round 1.
5. **Inventory or conception** — EXISTING: promise by promise, what is served, left, decided alone,
   never checked; goldens of the numbers already served, recorded on the intact commit. NEW:
   references, contract first and ALONE on `main` (PACT10), mockups for a screen, product
   decisions (Tensions 3); built by a plan run, invisible until activated; rounds start once the
   first screen runs. MIXED: inventory of the touched surface, its pattern file and a « do not
   change » list for every lane brief.
6. **Exit contract** — `gabarits/contrat-de-sortie.md`: closed list of screens, named references,
   criteria K1-K<n> each with an executable measure. A target absent from it never blocks later.
   A criterion that needs a tool that does not exist yet is judged by PAIRS until the tool exists.
7. **Instrument** — `gabarits/instrument-de-revue.md`: its launcher block, then its tour-0 CONTROL.
   If the control finds a real key, a real sending backend or a non-127.0.0.1 port, **stop tour 0**.
   The instrument scripts (capture, seeding, reset, launch, DOM measures) are not on `main`: the
   first L4 writes them from the template, in its working folder, and runs the DOM-measure script
   once on the intact commit (the K baseline).
8. **Registry + state** — `gabarits/registre.md` (one file per writer) and `gabarits/etat.md`,
   committed and pushed on the notes branch.

## A round

1. **Reviewers** (4-6 per round; 6 / 5 / 4 were used, rétro §3) — fresh, `relecteur-leger`, opus high, one role × one
   axis (function / simplicity / beauty × phone / desktop), own account, `gabarits/brief-relecteur.md`.
   They USE the product like its user and PROVE each finding (gestures + capture looked at +
   expected), graded S1-S4, against NAMED references; beauty by PAIRS (before/after, us/reference)
   plus DOM measures, never an absolute score alone; floor = qa-explorer STEP 2 oracles 1-10 +
   STEP 3 rules 1-12 (cite, never copy). Each writes its own findings file and, from round 2, its
   own counter-verification events file. Message ≤ 15 lines **(start)**.
   From round 2: FIRST counter-verify the scope's fixes with `vérifie`'s closed verdicts (ok /
   partiel / non-fait / faux / régression / déjà-présent, METHODE §C.4), twins first; attack every
   open class on its matrix (`gabarits/fiche-invariant.md`); THEN look fresh.
2. **Consolidation** (one opus, `gabarits/consolidation.md`) — each finding checked against the
   code (`file::symbol`, never `file:line` — METHODE anti-pattern 11), verdict written to its own
   events file; product choices ruled (Tensions 3); **classes named**: a root behaviour behind ≥ 2
   findings gets a fiche with the grepped places AND the field × condition matrix; the table of
   shared identifiers (CSS class, prop, `data-*`, HTTP code, event) with their owner; corrections
   written into the owner's plan (« Where corrections go ») and grouped into lanes.
3. **Test-writer** (sonnet, one per lane that carries a class or an S1-S2 data-loss / wrong-number
   fix; `gabarits/brief-lane.md` § « Test premier ») — after the consolidation, before the lanes:
   commits the proving tests, red, on `tests/T<n>-<lane>`, the branch its lane starts from. The fold
   refuses a lane whose diff touches those tests.
4. **Lane 0 — a global contract change goes ALONE, first** (error code, shared shape, shared
   component API): it owns the server AND every reader found by grep (API client, mocks, e2e
   specs), even in files of other lanes; green before the wave, with the table « what changes, who
   reads it ». A late 400 → 409 cost 5 CI round-trips (rétro §6.3). Found by CI mid-wave: no new
   lane starts; lanes in flight receive the table and rebase on it.
5. **Fix lanes** (`gabarits/brief-lane.md`, `lane-legere`, model from `plan_lanes.py`, at most ~5
   tasks per agent — « Token economy » 2) — worktrees launched ONE per message; red test, root cause, twins, one commit per fix. Local checks = eslint + flake8 /
   py_compile on their files + THE test they fix; no Docker, no neighbour suite, no build +
   Playwright per lane before the push (WOW23). Exits: **fixed** / **contested** (the finding is
   wrong — evidence) / **impossible** (not without weakening something — why); only the
   orchestrator drops a test.
6. **Fold, push, seam** — the orchestrator folds `--no-ff`, reading only the 15-line report and the
   lane's events file, then pushes. Then ONE seam lane alone on the assembled tree: greps every
   shared identifier on both sides, WALKS every screen of the tree on the instrument (what CI does
   not do), takes the « after » capture of each visible fix with the gestures the lane wrote, and
   looks at it — that capture is the fix's proof, not a gate. E2E specs are CI's, except under
   WOW23's rule (only when the full relevant set is faster locally than the CI job).
7. **CI** — a haiku scout reads each red log (≤ 10 lines back); the red goes to the lane owning the
   file; nothing disabled or exempted.
8. **Breaker per finding** — 3 attempts **(start)**: 1-2 by its lane, 3 by a fresh fixer one tier up,
   re-reviewed on that diff only; then « parked with decision » or « smallest unblocking change ».
9. **Waves and merge** — a round of more than ~80 corrections is cut into WOW23 waves
   (`plan_lanes.py --wave-size 80`), each merged by the queue the instant its CI is green, never a
   second wave on a red one; one fresh opus critiques the server diff of each wave before it
   merges (security, company/account isolation, data loss; error-autopilot's taxonomy). At each
   merge say the house merge line (CLAUDE.md « Deploys ») plus « <n> corrections pas encore
   contre-vérifiées : déployer maintenant ou après le tour suivant » — the deploy is Reda's
   gesture (on 19-20/11 a merge after round 1 would have put 3 regressions on `main`).
10. **Acceptance records** — when a wave ticks tasks of an audit group that carry an executable
    proof, the ORCHESTRATOR plays and commits `docs/audits/acceptation/<G>/<date>-<sha9>.md` (+
    `results.json`) before the push (CLAUDE.md 3-bis, `check_acceptation.py`). Reviewer verdicts
    never stand in for it; reviewers tick nothing.

## Stop, last round, final

- **Mechanical stop** — no new round once one holds: contract met; round cap (k, below); quota.
  « Dry » = two DIFFERENT reviewers on one scope with no new S1-S2 (agreement between evaluators
  ran 5-65 % among HUMAN usability evaluators — Hertzum & Jacobsen 2001; never measured for LLM
  reviewers). The curve never reaches zero: never aim for a dry round.
- **Last round** (the k-th) — every new finding is « avant le merge » (seen in the first hour,
  data loss, wrong number, common gesture broken) or « peut attendre » → `[ ]` tasks in the owner's
  plan. Only the first list is fixed.
- **Final** (NOT a round, its own reserve, always played before the last merge): ONE fresh
  targeted verification on the real screen + ONE adversarial critique of `git diff <T0 sha>..HEAD`
  server side. It is the Fable pass only if the run folded ≥ ~40 tasks or touched rule #4 / auth /
  architecture (CLAUDE.md, Fable case (a)); otherwise opus high. On 19-20/11 this step alone found
  2 blockers and 7 server corrections (rétro §3).
- Then: product choices taken alone restated in the module README, release claims, tear the
  instrument down, retro.

## Cost and stop (all values (start) unless sourced)

- Rounds allowed `k = min(3, floor((90 − u − r) / c))`, u = weekly quota used (%), **90** = stop line
  (leaves 10 points of the week to Reda), **r = 10** = reserve for the final, **c = 21** at the start
  = (74 − 10) / 3 (rétro §3: 74 points for tour 0 + 3 rounds + final, part from another session; the
  final is already in r, tour 0 is folded into c — an upper bound), then the measured cost of round 1, written to the state file. `k` counts EVERY round, the
  last included. k ≤ 0 → tour 0 only, on disk, resumed after the reset.
- When the next round does not fit, go straight to the final. Quota at 90 %: commit, push, write
  state, stop; the final is played at resume, never skipped, and nothing merges without it.
- Context of the orchestrator ≥ 70 % → write the state before continuing.
- The cost line is for Reda: never put a budget or countdown in an agent's prompt.
- Counter-verification: every fix while `non-fait + partiel` > 10 % **(start)**, then all S1-S2 +
  25 % of the rest (25 % from METHODE §C.4.2). Measured once: round 1 → 143 settled, 37 half,
  5 not, 3 regressions out of 191 counter-verifications (rétro §3; those four sum to 188, the
  source does not reconcile the gap).

## Where corrections go (the owner's plan, in THAT plan's format)

- Owner = `python scripts/check_ownership.py --owner-of <files>`, run in a worktree synced to
  `origin/main` (it reads the local `docs/ownership.yml`).
- A domain plan (`docs/plans/PLAN_<X>.md`, e.g. `PLAN_TACHES.md` — what 19-20/11 did, CI green):
  one-line tasks with `@lane @files @model @after`.
- An audit plan (`docs/plans/PLAN_AUDIT_*.md`): full v3 tasks (METHODE §C.2, the 14 clauses,
  `@model` mandatory) — `check_taches_cablage.py` is blocking; a fix whose `Files:` span several
  owners goes to `PLAN_AUDIT_TRANSVERSE.md` with `(@atomique: …)`. Before pushing, run
  `check_ownership.py`, `check_ancres_taches.py`, `check_taches_cablage.py` (METHODE §C.4.5).
- Other owners: `docs/PLAN.md` / `docs/ERROR_PLAN.md` → that file's one-line format + CODEMAP §10
  and `codemap_fingerprint.py --write` in the same commit; `docs/WEB_PLAN.md`,
  `WEB_ERROR_PLAN.md`, `FRONTEND_GAP_PLAN.md` → that file's format; `docs/backlog/*` (parked) →
  never: say it in the report.
- Never an invented format. Lanes: `plan_lanes.py` when the corrections are plan tasks with
  `Files:`; otherwise the consolidation's file → lane table, checked disjoint, said in the report.
- A decision Reda gives during the run goes into `docs/audits/decisions.yml` or
  `docs/claude-memory/` in the round's PR — never only in the run's state file.

## Tensions settled (each reads a CLAUDE.md rule; none amends it)

1. **WOW23 TEST ECONOMICS** — lanes run only the cheap checks above; the instrument is not a gate:
   it is the local stack that rule 3-bis already requires for live acceptance, and it follows
   `ci-avant-docker` (pushed code, in parallel with CI, never in its place).
2. **MERGE FLOOR (~100 unmerged)** — the waves of step 9 keep every PR under it.
3. **Questions (METHODE §B.6 vs « aucune question »)** — by default NEW and MIXED ask ONE batch of
   product decisions at the end of tour 0, recommendation first; EXISTING asks none. Under « no
   questions » every regime rules by the written rule (simplest for the user, else the mockup,
   else the named references), logs each choice with its cost-if-wrong, keeps it reversible and
   never records it as Reda's decision.
4. **Cost (Fewest steps; METHODE §B.3 8 M cap)** — the 8 M cap governs audits; L4 is never
   auto-picked, announces its cost first and stays inside the formula.
5. **Fable** — only CLAUDE.md's cases (a)(b)(c), as in « Final ».

## Retro (≤ 5 min, house rules on bloat)

Per class: « would the system catch it alone next time? » In L4 the class's read-only test IS its
guard; a further guard is a `[ ]` task of its owner, one per CLASS in an existing family, never
one per finding (METHODE anti-pattern 15); a guard under `scripts/` is never slipped into a docs PR.
CI bug classes → memory `plan_drain_ci_bug_classes`; the registry curve and every measured
(start) value → the state file.
