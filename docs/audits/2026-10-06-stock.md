## 2. Spécification (phase 2)

**Scénarios H×H (joués en direct à L2)** — stimulus → réponse → mesure :
S-A prix : l'utilisateur corrige le prix de vente d'un produit → un devis brouillon qui l'utilise le reflète
au recalcul, un devis envoyé/accepté reste figé (prix négocié intouchable), écran = `/proposal`.
S-B aller-retour produit : créer → rouvrir → enregistrer sans toucher ⇒ objet serveur byte-identique.
S-C `prix_achat` absent de tout JSON servi à un rôle Commercial non autorisé, du portail, des PDF client.
S-D achat bout en bout : BCF → envoi → réception partielle → réception solde → facture fournisseur →
paiement ⇒ stock + valorisation + reste à payer cohérents ; annuler la réception ⇒ stock restauré.
S-E étanchéité : objets stock/achats d'une autre société (ids substitués) ⇒ 404, jamais 403 ni donnée.
S-F correction après coup : éditer une ligne de BCF déjà reçue ou une facture fournisseur validée ⇒ refus
clair ou révision tracée, jamais d'écart silencieux stock ↔ valorisation.

**Saisie → consommateurs.**

| Saisie | Écrite par | Lue par |
|---|---|---|
| prix de vente produit | fiche produit, import, `seed_catalogue` | générateur devis, lignes devis, moteur `/proposal`, CRM, catalogue B2B |
| `prix_achat` | fiche produit, réception (coût), prix fournisseur | indicateur de marge générateur, valorisation, reporting — JAMAIS client |
| prix fournisseur / tarif | fiche fournisseur, import tarif | BCF (pré-remplissage), historique, réappro |
| quantité en stock | mouvements (réception, sortie chantier, ajustement, inventaire) | liste stock, réservations, ATP, alertes, valorisation |
| ligne BCF (qté, PU, TVA) | BCF | réception, facture fournisseur, PDF BCF, dashboard achats |
| fiche produit (marque/description/garantie) | fiche, `seed_catalogue` | PDF devis (fiches produit), portail |

**Chaîne documentaire 1:N.** produit 1-N prix fournisseurs ; BCF 1-N réceptions ; réception 1-N mouvements ;
BCF 1-N factures fournisseur ; facture fournisseur 1-N paiements / avoirs ; devis → chantier → sorties de
stock ; produit 1-N lignes de devis (copié ? référencé ? recalculé ?).

**Seuils.** S1-S2 ⇒ tâche ; S3 ⇒ tâche si effort ≤ M ; S4, style, durcissement hypothétique ⇒ liste
OPTIONNELLE. Chiffre client / argent / multi-société : toujours correctness, CONFIRMÉ seulement sur preuve
exécutée.

**Détecteurs prévus (4-a).** `check_parked_apps`, `check_services_appeles`, `check_ecrans_atteignables`,
`rapport_backend_sombre`, `check_api_shapes`, `check_api_contract`, `check_openapi_shapes`,
`check_tests_source_regex`, `check_invariants`, `core/event_coverage.py` (signaux stock/achats),
`lint-imports`, `makemigrations --check --dry-run stock achats` (conteneur), `audit_coherence` (aucune règle

## 8. Non-risques consignés (valides tant que l'hypothèse tient)

- **Lecture IDOR objet** — tous les viewsets stock/achats héritent de `CompanyScopedModelViewSet` /
  `TenantMixin` : un id d'une autre société en LECTURE renvoie 404 ; `perform_create` force `company`
  partout (hypothèse : `request.user.company_id` renseigné). Ce sont les ÉCRITURES de FK qui fuient
  (C-ASTK-001).
- **Numérotation** — BCF, REC, RF, FF, AVF passent tous par `create_with_reference` ; aucun `count()+1` dans
  stock/achats (grep).
- **Quantité totale** — `record_stock_movement` pose `SELECT … FOR UPDATE` dans une transaction ; seuls
  écrivains hors service : `views/mouvement.py:176` (C-ASTK-006) et le champ écrivable du serializer produit
  (C-ASTK-005) ; `check_mouvement_stock_service.py` : 4 sites allowlistés.
- **Double « Installé »** — `select_for_update` + drapeau `consomme` + plancher ERR80 : un second passage ne
  re-sort pas.
- **Sur-paiement fournisseur** refusé deux fois (serializer + `verrouiller_facture_fournisseur_et_verifier
  _solde`), CHECK DB montant > 0 ; imputation d'avoir plafonnée à `min(disponible, solde)`.
- **Jeton portail fournisseur** — 256 bits, 404 indistinct inconnu / révoqué / expiré, objets filtrés par
  société ET fournisseur du jeton ; confirmation d'un BCF d'un autre fournisseur → 404 (testé).
- **Devis accepté / refusé / expiré** jamais recalé par `produit_modifie` (filtre de statut, test
  `test_accepte_refuse_expire_ne_bougent_jamais`) ; prix négocié = définition unique partagée PVSYNC /
  composition.
- **`prix_achat` côté client** — retiré du `ProduitSerializer` sans `can_view_buy_prices` ; aucun PDF ni
  JSON CLIENT ne le porte (la fuite C-ASTK-002 est INTERNE, entre rôles).
- **Kiosque de quai public** — code 8 caractères `secrets`, throttle dédié, réponse minimale, idempotent.
