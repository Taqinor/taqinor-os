## 2. Spécification (phase 2)

- H×H S-1 : un ticket créé deux fois (double clic, rejeu portail) ⇒ un ticket ; un ticket résolu se rouvre avec trace.
- H×H S-2 : le SLA d'un ticket n'a qu'UNE définition (création → résolution, pauses), identique écran / rapport / alertes.
- H×M S-3 : la garantie d'un équipement part de la date de réception et suit un remplacement (le neuf hérite ou redémarre selon la
  règle) ; un ticket sous garantie n'est pas facturé.
- H×M S-4 : chaque viewset / action / tâche / page à jeton borne la société ; un jeton public ne donne accès qu'à son ticket.
- M×M S-5 : chaque événement émis a un abonné vivant (`equipement_remplace`, `abonnement_monitoring_resilie` : abonnés sans
  émetteur) ; une alerte monitoring n'est émise qu'une fois par épisode.

Seuils : S1 fuite locataire / perte / facture ou garantie fausse chez le client ; S2 saisie écrasée, geste cassé ; S3
contournement ; S4 cosmétique.
