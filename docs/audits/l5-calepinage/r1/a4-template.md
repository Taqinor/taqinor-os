## PARTIE 2 — Mécanique d'ajout d'un groupe v3 (vérifiée par lecture des scripts)

### 2.1 Où et sous quelle forme (METHODE §C.2 / §D.3)
Exact : « Forme : `- [ ] <ID> — **<Verbe + objet + fin bornée>** : ` puis les 14 clauses enchaînées, chacune ouverte par son libellé exact, `Files:` en DERNIER puis `(ROUTINE|SCHEMA|ARCH|DECISION|AUTH|COST) (@after: …) (@lane: …) (@model: …)`. Cible ≤ 2 400 caractères. » Une seule ligne physique (plan_lanes ne lit que la première).
Les 14 libellés dans l'ordre (`CLAUSES_AUDIT_V3`, check_taches_cablage.py) : `Constat`, `Given`, `Persistance`, `Emplacement`, `Code net`, `Appelants`, `Assertions existantes`, `Jumeaux`, `Listes figées`, `Contrat partagé`, `Test rouge d'abord`, `Preuve en direct`, `Hors périmètre`, `Files`. (METHODE : clause 2 = `Given … When … Then` ; clause 14 = `(gen <sha> …)` puis `Files:` ; `(gen manuel <sha7>)` tant que le générateur ne les produit pas.)
En-têtes (§C.2 « En-têtes », §D.3.7) : nouveau groupe `## Groupe <G> — audit <mot> du <date> (dossier …) · format v3`, puis `### <G> — M0 contrats (seuls sur main d'abord)` / `M1 bloquant-fondateur` / `M2` / `M3 nettoyage et gardes` / `GATED (ne PAS auto-construire)`. MAIS « Une tâche nouvelle pour un ancien groupe s'écrit sous un en-tête `## Groupe <G> — complément du <date> · format v3` ou `### <G> — ÉCARTS vérifie <date> · format v3` ». Insérer JUSTE AVANT `## DONE LOG` (ici l.662). Append-only : ne jamais réécrire/réordonner/recocher un autre groupe. « Chaque groupe se termine par UNE tâche `@acceptation` que les lanes ne construisent jamais. » En-têtes déjà utilisés dans ce plan : `### ACAL — ÉCARTS vérifie 2026-11-20 · format v3`, `### ACAL — constat d'acceptation du 2026-11-19 (ACAL356, PA2.5) · format v3`.
Interdits par relecture (§C.2) : ancre `fichier:ligne` seule ; fichier de test portant un id de tâche ; second marqueur `fichier(s) :` ; « Si (a)/(b) » ; deux comportements dans une tâche ; `@after` vers tâche ouverte d'un AUTRE fichier (sauf moitié de contrat M0) ; `@model: opus` pour règle #4, argent, auth, `core`. §C.4.5(e) : une tâche ÉCART ne cite jamais un `C-<G>-NNN` du dossier d'origine (constat = `C-<G>-VER<n>-NNN`) ; pour une fonctionnalité neuve aucun script ne contrôle le format du `C-…` (seul le mot « Constat » est exigé).

Chaque ligne : 14 libellés, aucun `n/a` nu, `(@model: …)`, `(ROUTINE|SCHEMA|…)`, `Files:` en dernier avec chemins complets entre backticks, un seul `Files:`. 4. Chaque fichier de `Files:` : propriétaire au registre (sinon éditer `docs/ownership.yml` dans la même PR) et propriétaire `calepinage` seul ; specs d'acceptation `frontend/e2e/acceptation/*` = `deploy`. 5. Moitiés back+front : contrat d'abord (M0, `apps/calepinage/contract_samples/*.json` cité des deux côtés), `@after` du front sur le back. 6. Nouvel écran sous `frontend/src/features/calepinage/**` : `atelier/onglets.js` (ou `module.config.jsx`) dans `Files:` + clause « onglet monté dans … / route déclarée + entrée de nav ». 7. `` `fichier::symbole` `` seulement pour des symboles existants (hors « Test rouge d'abord »). 8. Une tâche `@acceptation` en fin de groupe. 9. Gardes avant push : `python scripts/check_ownership.py`, `python scripts/check_ancres_taches.py`, `python scripts/check_taches_cablage.py`, `python scripts/audit_registre.py --check`, `python scripts/check_decisions.py`, `python scripts/check_plan_taches_mixtes.py`, `python scripts/check_build_order.py`, `python scripts/plan_lanes.py docs/plans/PLAN_AUDIT_CALEPINAGE.md`, `python -m unittest scripts.tests.test_plan_lanes`. Docs-only ⇒ seuls les jobs rapides tournent (~2 min).
