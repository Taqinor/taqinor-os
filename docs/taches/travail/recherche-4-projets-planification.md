# Recherche L3 n°4 — Projets et planification (une personne, espace privé)

Sources : pages lues dans cette session (URL entre parenthèses) ; « via recherche » = extrait de résultat de recherche, page non lue. 15 recherches utilisées.

## 1. Phase de planification
- **GTD Natural Planning Model, 5 étapes dans l'ordre** : buts et principes (le « pourquoi »), vision du résultat, brainstorming, organisation, prochaines actions (gettingthingsdone.com/2024/11/the-natural-planning-model/ ; détail des étapes par résumés tiers, le guide d'Allen p. 10-11 n'est pas lu).
- **Prochaine action** : à la revue, chaque projet doit avoir « au moins une prochaine action » (gettingthingsdone.com/2018/08/episode-43-the-power-of-the-gtd-weekly-review/).
- **Shape Up** : l'appétit est « le temps qu'on veut y consacrer », pas une estimation ; « les estimations partent d'une conception et finissent par un nombre » ; temps fixe, périmètre variable (basecamp.com/shapeup/1.2-chapter-03). Pour un solo : un seul champ « combien de temps ça vaut » (`echeance` ou semaines), jamais d'heures par tâche.
- **Pre-mortem (Klein, HBR 2007)** : supposer le projet échoué et lister les causes plausibles (hbr.org/2007/09/performing-a-project-premortem). Le « +30 % » cité mesure le NOMBRE de raisons trouvées, pas leur justesse (corporate.jasoncollins.blog/premortem, source secondaire).
- **PARA** : Projets = « efforts à court terme avec un but » ; voir §9 (fortelabs.com/blog/para/).
- OKR personnels, WBS : non lus — NON VÉRIFIÉ.
- **Tient en 2 min sur téléphone** : nom + « fini quand… » + échéance facultative + première action. Pré-mortem et brainstorming = AVANCÉ, jamais bloquants.

## 2. Vues
- Marvin : Planning Ahead en Kanban / 3 colonnes / 2 colonnes (help.amazingmarvin.com/strategies/planning/planning-ahead). Things : un projet = une liste avec des « Headings » (culturedcode.com/things/guide/).
- **Vues réellement utilisées par un solo : non établi** (aucune donnée d'usage trouvée).
- Coût mobile (jugement, non sourcé) : liste à sections nul ; kanban médiocre ; Gantt illisible.
- Reco : liste à sections (`Section` du socle). Kanban = AVANCÉ bureau. Gantt, calendrier, tableau = ÉCARTÉS v1 (le jour prévu donne déjà le calendrier).

## 3. Jalons, phases, dépendances
- **Linear** : jalon = « étape du cycle de vie d'un projet » ; icône losange, le prochain jalon incomplet est en jaune ; progression dérivée des tâches rattachées (linear.app/docs/project-milestones).
- **Asana** : tâche en attente = bandeau jaune ; notification quand le bloqueur change d'échéance et quand il est fini ; avec plusieurs bloqueurs, notifiée seulement quand tous sont finis (asana.com/inside-asana/dependencies). Effet sur « Mes tâches » : non lu (l'article d'aide principal n'a pas rendu son texte).
- **ClickUp** : avertissement désactivable avant de clore une tâche « en attente d'une autre », non bloquant (help.clickup.com/hc/en-us/articles/6304410420759, via recherche ; page refusée 403).
- **OmniFocus** : projet séquentiel = seule l'action du haut est « Available », les suivantes « Blocked » ; en vue « Available » elles sont masquées, sinon grisées ; projet « On Hold » = ses actions « Unavailable » (support.omnigroup.com/documentation/omnifocus/universal/4.8/en/glossary ; .../mac/2.7/en/projects/).
- Conséquence pour la liste du jour : une tâche bloquée y est **masquée** (OmniFocus) ; un bandeau suffit (Asana). Choix : masquée de « Ma journée », visible dans le projet avec « attend : X ».
- **Chemin critique** : aucune aide trouvée pour un usage solo. Argument : il arbitre entre ressources ; seul, on fait une chose à la fois, l'ordre vient de la priorité et de la prochaine action. HORS SUJET.
- « Bloquée par » = AVANCÉ (un bloqueur par tâche ; `en_attente_de` texte libre déjà au socle). Phases = `Section` datée ; jalon = tâche marquée, pas un objet.

## 4. Avancement et santé
- **Linear** : le graphe d'avancement compte les points d'estimation, ou **1 point par tâche** sans estimation ; la portée est tracée (révèle la dérive) ; les projections n'apparaissent qu'après ≥ 1 semaine de données ; l'avancement peut baisser si la portée baisse (linear.app/docs/project-graph).
- **Piège du pourcentage** : « les listes de tâches grossissent quand on découvre le travail » ; peu de tâches ouvertes peut signifier « pas encore défini » (basecamp.com/shapeup/3.4-chapter-12). Hill chart : « en réflexion » (montée) vs « en exécution » (descente).
- **Santé** : Asana = on track / at risk / off track / on hold, rappel hebdomadaire (via recherche ; aide non lue). Linear = 3 états, icône signalant une mise à jour manquée (via recherche) ; gris = pas d'update courante (linear.app/docs/initiatives).
- **Projet sans prochaine action** : OmniFocus l'appelle « stalled », filtre « projet actif sans action restante » (glossaire cité). Cohérent avec GTD ci-dessus.
- Pour un solo, tout est calculable, sans saisie de statut : (a) prochaine action manquante, (b) aucune tâche faite depuis N jours (N n'est pas sourcé : réglage, défaut à fixer), (c) échéance du projet vs tâches ouvertes datées après elle, (d) tâches faites / ouvertes, montré avec le nombre de tâches ouvertes et la date de la dernière tâche faite, jamais seul. Le vert/orange/rouge reste une conclusion dérivée, pas une saisie.

## 5. Priorité entre projets
- **Marvin** : « Orbit » = « votre zone de focus actuelle » ; « Backburner » = non-actionnable (amazingmarvin.com/features/funnel/). Répartition en pourcentage entre projets : **non trouvée**.
- **OmniFocus** : On Hold = « pas dans l'intention de travailler maintenant mais peut-être plus tard » ; Dropped = abandonné ; revue en vue « Remaining » (glossaire cité). **Things** : Someday = projets « non engagés bientôt », à relire régulièrement (culturedcode.com/things/guide/). Linear : priorité + statut (Proposed/Planned/Active/Completed/Canceled) (linear.app/docs/initiatives).
- **WIP** : le Kanban Guide 2020 demande de définir « comment le WIP est contrôlé » ; le mécanisme tiré (« on ne tire du travail que s'il y a de la capacité ») ; dépassement « rare et explicite » (kanbanguides.org/the-kanban-guide/2020.7, extrait par résumé). **Aucun nombre sourcé pour un solo** : « 3 à 7 Areas » vient de blogs Things non officiels.
- Reco : `priorite` 0-3 du socle + statut actif / en_pause (« un jour ») ; plafond de projets actifs = avertissement doux, valeur par défaut posée comme choix par défaut, jamais bloquante.

## 6. Modèles
- **Todoist** : export/import CSV (sections, tâches, priorité, dates) ; 300 tâches max ; l'import ne s'annule pas ; la date de début d'une récurrence se perd (todoist.com/help/articles/208821185-Project-templates).
- **Asana** : la tâche à l'échéance la plus tôt est calée sur la date choisie, les autres suivent du même écart ; changer ensuite la date d'un projet existant ne décale RIEN (forum communautaire, pas l'aide officielle).
- Things, ClickUp, Notion, Trello, Basecamp, Odoo : non lus sur ce point.
- Reco : « enregistrer comme modèle » (sections + tâches en `J+n` depuis le début, sans notes) ; au lancement UNE date, tout se cale, aperçu avant création.

## 7. Revue hebdomadaire
- GTD : évaluer « un par un » projets et résultats, « au moins une prochaine action » chacun (page citée). Reste de la check-list : NON VÉRIFIÉ.
- Linear recommande une mise à jour hebdomadaire ; Asana envoie un rappel hebdomadaire (via recherche).
- Questions par projet (dérivées, non sourcées telles quelles) : prochaine action ? avancé cette semaine ? échéance tenable ? garder, mettre en pause, abandonner ? Une carte par projet, 4 boutons.

## 8. Clôture
- OmniFocus : projet « Completed » classé en bibliothèque ; « Dropped » = masqué hors vue « All » et marqué pour archivage futur ; les actions actives d'un projet complété le restent (support.omnigroup.com/documentation/omnifocus/mac/2.7/en/projects/). Todoist : archiver retire des projets actifs, désarchiver rend « tâches, commentaires, fichiers » (recherche ; sort des tâches terminées non confirmé).
- Reco : `termine` demande « atteint / abandonné / mis de côté » + une ligne facultative de bilan ; statistiques gardées (dates, tâches faites, durée réelle) ; `archive` = masqué mais lisible.

## 9. Objectifs au-dessus des projets
- PARA : Areas = parties de la vie ou du travail qui « demandent une attention continue » (Santé, Finances, Marketing) (fortelabs.com/blog/para/). Things : Area = ce qui « soutient une ambition continue » ; Projet = « plus d'une étape » (culturedcode.com/things/guide/).
- Solo : les Areas servent de regroupement (« Chantiers », « Administratif ») ; objectifs trimestriels mesurés = couche en trop (aucune source sur leur utilité à un solo). Reco : Area = AVANCÉ, simple libellé ; OKR = ÉCARTÉ.

## 10. Plaintes des solos
- Sources faibles (blogs d'éditeurs, forums ; plusieurs vendent un concurrent) : outils d'équipe jugés lourds, collaboration payée sans usage, Notion « peu systématique », Trello trop mince. **Non établi** quantitativement.
- Pièges concrets : dates de modèle qui ne suivent pas (Asana), import irréversible (Todoist), mention « bloquée » restée après la fin du bloqueur (forum Asana).

## À COPIER (ordre)
1. Création minimale : nom + « fini quand… » + première action · GTD/OmniFocus · une prochaine action évite le projet bloqué.
2. Liste à sections, sections = phases datées · Things/Todoist · seule vue utile sur téléphone.
3. Projet sans prochaine action = « à débloquer » · OmniFocus « stalled » + GTD · se calcule, ne se saisit pas.
4. Santé calculée (prochaine action, dernière tâche faite, échéance menacée) · Linear/Asana, sans saisie · zéro entretien.
5. En pause / un jour (actions masquées du jour) · OmniFocus On Hold, Things Someday.
6. Tâche bloquée masquée de « Ma journée », visible au projet · OmniFocus.
7. Jalon = repère daté sur le projet · Linear · simple.
8. Modèle depuis un projet, une date de lancement, décalage relatif, aperçu · Asana/Todoist (leurs défauts corrigés).
9. Revue hebdo : une carte par projet, 4 gestes · GTD.
10. Clôture avec issue + une ligne de bilan, statistiques gardées · OmniFocus.
11. Avancement = faites/ouvertes avec les deux nombres · Linear, Shape Up.
12. Plafond doux de projets actifs · Kanban/Marvin Orbit.
